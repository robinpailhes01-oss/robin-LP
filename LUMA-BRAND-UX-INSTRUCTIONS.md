# LUMA — WEBSITE BRAND & UX INSTRUCTIONS

Instructions exclusives pour la conception du site internet Luma

Version : septembre 2026

---

## 1. Objectif du site

Le site Luma doit permettre à un dirigeant de comprendre rapidement trois choses :

1. Luma comprend la charge mentale et les interruptions de son entreprise.
2. Luma construit une infrastructure personnalisée pour prendre en charge ce qui est répétitif.
3. Le résultat est une entreprise plus simple et plus légère à gérer.

Le site ne doit pas donner l’impression d’un site d’agence IA classique.

Il ne doit pas être centré sur :

- les outils ;
- les modèles ;
- les workflows techniques ;
- le jargon ;
- les robots ;
- les automatisations décoratives.

Le site doit être centré sur :

- le problème du dirigeant ;
- la simplicité ;
- le résultat ;
- le sur-mesure ;
- la fluidité.

---

## 2. Principe directeur UX

> **Complexe derrière. Simple devant.**

Le site doit incarner ce principe.

Même si les systèmes Luma sont complexes, l’expérience utilisateur doit être :

- simple ;
- calme ;
- fluide ;
- évidente ;
- premium.

---

## 3. Sensation recherchée

Quand un prospect arrive sur le site, il doit ressentir :

- légèreté ;
- maîtrise ;
- clarté ;
- calme ;
- confiance ;
- intelligence ;
- simplicité.

Il ne doit pas ressentir :

- surcharge ;
- technicité ;
- confusion ;
- futurisme ;
- froideur ;
- gadget.

---

## 4. Direction artistique

### Style général

- très épuré ;
- beaucoup d’espace blanc ;
- très peu de couleurs ;
- typographie forte ;
- photographie humaine ;
- interfaces simplifiées ;
- animations lentes et fluides ;
- aucune décoration gratuite.

### Palette

| Rôle | Couleur |
| --- | --- |
| Fond principal | `#F7F7F4` |
| Texte principal | `#111214` |
| Accent Luma | `#315CFF` |
| Surface secondaire | `#E7E8E8` |
| Texte secondaire | `#72757A` |

Le bleu ne doit jamais envahir l’interface.

Il doit servir de signal.

---

## 5. Typographie

Utiliser une excellente sans-serif.

Direction :

- Geist ;
- Inter ;
- Helvetica Now ;
- Neue Haas Grotesk ;
- Suisse ou équivalent.

### Règles

- titres très grands ;
- texte court ;
- peu de poids différents ;
- forte respiration ;
- hiérarchie évidente ;
- pas de typo futuriste.

---

## 7. Hero

Le hero doit être très différent d’un hero classique.

Ne pas commencer par :

> Agence IA pour automatiser votre entreprise.

Commencer par une expérience.

### Concept : conversation live

Une conversation apparaît progressivement.

Exemple

22:47

Client :

> Bonsoir, vous avez encore une disponibilité samedi ?

Luma répond.

Puis une deuxième demande arrive.

Elle est qualifiée.

Puis un rendez-vous est créé.

Puis :

> **Traité par Luma ✓**

Ensuite la conversation disparaît progressivement.

Puis apparaît :

Vous n’avez rien eu à faire.

Sous-titre :

> Luma construit des infrastructures IA sur mesure qui prennent en charge les tâches qui monopolisent votre entreprise.

CTA principal :

> **Découvrir ce qu’on peut automatiser**

CTA secondaire facultatif :

> Voir une démo

---

## 8. Hero — règles visuelles

Le hero doit être :

- plein écran ou presque ;
- très calme ;
- peu chargé ;
- conversation centrée ;
- fond blanc ou noir selon version ;
- animation lente ;
- aucun robot ;
- aucun visuel futuriste ;
- aucune pluie d’icônes.

Le produit doit se comprendre par le mouvement.

---

## 9. Section problème

Objectif :

faire reconnaître le quotidien du dirigeant.

Titre possible :

Votre entreprise vous sollicite trop.

Puis éléments simples :

- demandes clients ;
- devis ;
- relances ;
- questions ;
- rendez-vous ;
- suivi ;
- tâches répétitives.

Phrase :

> Individuellement, aucune de ces tâches n’est compliquée.
> Additionnées, elles prennent vos journées.

---

## 10. Section promesse

Très peu de texte.

Moins à gérer. Plus à construire.

Puis :

> Luma prend en charge les tâches répétitives et les demandes qui monopolisent votre quotidien.

Visuellement :

- beaucoup d’espace ;
- une seule animation ;
- aucun élément décoratif inutile.

---

## 11. Section infrastructure sur mesure

Très importante.

Le site doit expliquer clairement que Luma ne vend pas un outil standard.

Titre :

Pas un outil de plus. Une infrastructure pensée autour de votre entreprise.

Montrer :

- vos outils ;
- vos process ;
- votre ton ;
- vos équipes ;
- vos données ;
- vos clients.

Puis :

> Luma s’adapte à votre fonctionnement. Pas l’inverse.

---

## 12. Visualisation système

Créer un schéma très simple.

Exemple :

```
Demande client
↓
Luma
↓
Réponse + qualification + CRM + rendez-vous
```

Utiliser le code graphique :

**The Luma Flow**

Une ligne qui traverse la section.

Elle représente la circulation de l’information.

---

## 13. Section cas d’usage

Ne pas lister 30 automatisations.

Montrer quelques cas concrets.

**Service client**

> Répondre aux demandes récurrentes.

**Qualification**

> Identifier les prospects réellement intéressés.

**Relance**

> Recontacter automatiquement les demandes sans réponse.

**Rendez-vous**

> Proposer et enregistrer un créneau.

**CRM**

> Mettre à jour les informations automatiquement.

**Process internes**

> Faire circuler les informations sans intervention manuelle.

---

## 14. Section avant / après

Très bonne section pour la conversion.

### Avant Luma

- interruptions ;
- demandes oubliées ;
- réponses tardives ;
- tâches répétitives ;
- suivi manuel.

### Avec Luma

- demandes traitées ;
- réponses immédiates ;
- informations centralisées ;
- suivi automatique ;
- plus d’espace mental.

Titre :

Une entreprise qui grandit ne devrait pas devenir plus lourde à gérer.

---

## 15. Section preuve

Luma doit montrer des résultats réels dès qu’ils sont disponibles.

Exemples :

- temps récupéré ;
- demandes traitées ;
- taux de réponse ;
- leads qualifiés ;
- relances effectuées ;
- rendez-vous générés.

Ne jamais inventer de chiffres.

Si les chiffres ne sont pas encore disponibles :

- utiliser des cas d’usage détaillés ;
- montrer le fonctionnement ;
- montrer le contexte avant/après.

---

## 16. Section méthode Luma

Expliquer le process en 4 étapes.

**1. Comprendre**

Audit du fonctionnement actuel.

**2. Identifier**

Repérer ce qui consomme du temps inutilement.

**3. Construire**

Créer l’infrastructure personnalisée.

**4. Optimiser**

Faire évoluer le système selon les besoins.

Titre :

On commence par comprendre votre entreprise. Pas par vous vendre un outil.

---

## 17. Section “pour qui”

Luma n’est pas destiné à tout le monde.

Message :

Pour les entreprises qui ont déjà du volume, mais plus envie de tout gérer manuellement.

Exemples :

- PME ;
- hôtellerie ;
- restauration ;
- salles de sport ;
- cabinets ;
- services ;
- entreprises locales ;
- réseaux ;
- équipes commerciales.

---

## 18. FAQ

Questions recommandées :

- Est-ce que Luma remplace mon équipe ?
- Est-ce que l’agent parle comme nous ?
- Peut-il être connecté à nos outils ?
- Est-ce que tout est personnalisé ?
- Peut-on commencer par un seul process ?
- Combien de temps faut-il pour mettre le système en place ?
- Peut-on intervenir si nécessaire ?
- Comment sont gérées les données ?
- Est-ce que cela fonctionne sur WhatsApp ?
- Est-ce que Luma peut évoluer avec l’entreprise ?

---

## 19. CTA final

Le CTA ne doit pas être agressif.

Titre :

Et si votre entreprise vous interrompait moins ?

Sous-texte :

> On identifie ensemble ce qui vous fait perdre du temps et ce qui pourrait fonctionner sans vous.

CTA :

> **Parler de mon entreprise**

Alternative :

> **Découvrir ce qu’on peut automatiser**

## 21. Animations

Les animations doivent incarner la fluidité.

### À utiliser

- apparition progressive ;
- fade ;
- slide subtil ;
- ligne qui se trace ;
- flux de conversation ;
- micro-transitions ;
- scroll fluide ;
- éléments qui se connectent.

### À éviter

- 3D futuriste ;
- particules ;
- robots ;
- animations agressives ;
- effets glitch ;
- néons ;
- interactions inutiles.

---

## 22. Interface conversationnelle

Créer une UI propre à Luma.

Ne pas copier exactement WhatsApp.

### Composants

- bulle client ;
- bulle Luma ;
- timestamp ;
- état “traité” ;
- état “qualifié” ;
- action créée ;
- rendez-vous créé.

Cette interface peut vivre dans :

- hero ;
- cas client ;
- démos ;
- carrousels ;
- reels ;
- landing pages.

- dirigeants ;
- équipes ;
- environnement réel ;
- calme ;
- temps retrouvé ;
- moins d’interruptions ;
- moments de concentration ;

Éviter :

## 24. Copywriting

### Ton

- simple ;
- direct ;
- humain ;
- calme ;
- précis.

### Règles

- phrases courtes ;
- peu de jargon ;
- pas de surpromesse ;
- parler du quotidien ;
- toujours traduire la technologie en bénéfice ;
- ne pas dire “révolutionner” ;
- ne pas dire “solution innovante” ;
- ne pas dire “puissance de l’IA” sans contexte.

---

> Transformez votre entreprise grâce à l’intelligence artificielle.

## 26. Mobile

Le site doit être conçu mobile-first.

Sur mobile :

- titres courts ;
- gros espaces ;
- conversations très lisibles ;
- CTA visibles ;
- aucune surcharge ;
- animations simplifiées ;
- vitesse prioritaire.

---

## 27. Accessibilité

Maintenir :

- bon contraste ;
- textes lisibles ;
- tailles suffisantes ;
- boutons identifiables ;
- animations désactivables si nécessaire ;
- contenu critique disponible sans animation.

---

## 28. Page “À propos”

Ne pas faire une page centrée uniquement sur l’équipe.

Elle doit expliquer :

- pourquoi Luma existe ;
- quelle frustration a déclenché le projet ;
- quelle vision de l’entreprise Luma défend ;
- pourquoi le sur-mesure compte ;
- comment Luma travaille.

Message clé :

> **La technologie ne devrait pas rendre votre entreprise plus complexe. Elle devrait faire disparaître une partie de la complexité.**

---

## 29. Page solution / service

Chaque page doit suivre :

1. problème ;
2. impact quotidien ;
3. ce que Luma prend en charge ;
4. fonctionnement ;
5. personnalisation ;
6. preuve ;
7. CTA.

---

## 30. Règle finale

Chaque section du site doit passer ce test :

> **Est-ce que cela rend le bénéfice plus clair, ou est-ce que cela ajoute du bruit ?**

Si cela ajoute du bruit :

supprimer.

Le site Luma doit être la preuve visuelle de la promesse Luma :

> **Complexe derrière. Simple devant.**
